# 조사 프로토콜

영상의 모든 문구와 수치는 출처가 있어야 한다. 지어낸 숫자, 기준 연도를 모르는 숫자, 다른 회사와 섞인 숫자는 넣지 않는다.

## 1. 대상 특정
- 이름이 같은 회사나 서비스가 흔하다. 도메인, 대표자, 소재지 중 두 가지 이상으로 같은 대상임을 확인한다.
- 가장 강한 단서는 사용자 이메일 도메인, 사용자가 준 URL, GitHub 저장소다.

## 2. 조사 범위 (읽기 전용 에이전트에 위임, `model: sonnet`)
- **공식 사이트**: 소개, 대표 인사말, 연혁, 사업·기능, CI(로고·컬러) 페이지.
- **공식 블로그·보도자료**: 네이버 블로그와 뉴스는 WebFetch가 막히므로 curl에 데스크톱 User-Agent를 붙인다.
  - 글 목록: `https://blog.naver.com/PostTitleListAsync.naver?blogId=<id>&currentPage=1&countPerPage=30`
  - 본문: `https://m.blog.naver.com/PostView.naver?blogId=<id>&logNo=<no>`
- **제3자 기사**: 수주, 과제, 전시, 수상. 회사 이름이 본문에 나오는지 확인한다.
- **개인 서비스·사이트**: 랜딩 카피 원문, meta/og description. 비공개 저장소는 `gh` 읽기 전용 명령으로 본다(README, 트리, 설정, 커밋 수와 생성일).
- **브랜드 자산**: 로고 이미지의 정확한 URL, 컬러 hex(CSS나 CI 페이지), 폰트 이름, 마스코트 유무.

에이전트에는 다음 순서로 보고하게 한다: 대상 특정 근거 → 사실 목록(출처 URL) → 영상용 수치 후보(출처·신뢰도) → 카피 원문 → 브랜드 자산 → 확인 못 한 것.

## 3. 검증
- 영상에 크게 들어가는 핵심 수치는 에이전트 보고만 믿지 말고 원문 문장을 직접 가져와 확인한다.
- 같은 대상의 자료끼리 수치가 다르면 사용자에게 어느 쪽을 쓸지 묻는다. 두 버전을 모두 렌더할 수 있게 설정값 하나로 분리해 둔다.
- 채용 사이트 같은 자동 수집 데이터(매출, 직원 수)는 기준 연도가 불명확하면 뺀다.
- 컨소시엄 과제나 공동 사업의 총예산은 회사 몫이 아니면 금액을 넣지 않고 참여 사실만 쓴다.
- 기술 세부(모델명, 인프라)는 사용자가 원하지 않으면 빼고, 대상의 가치 중심으로 쓴다.

## 4. 사용자에게 보고할 것
- 영상에 쓴 사실마다 출처 링크
- 뺀 수치와 그 이유
- 확인이 필요한 수치(최신 여부가 불명확한 것 등)
